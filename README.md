# SettleRecon v2｜机构对账单增量重算与数据质量闸门

一个面向证券公司机构业务后台的可运行个人项目。项目不试图重造核心清算系统，而是优化一个很小但具体的环节：日终对账单生成后，如果某个税费批次迟到或被更正，传统全量跑批需要重新计算全部机构账户；本项目按“账户 + 对账日”生成输入指纹，只重算真正受影响的账户，并在出单前执行资金和持仓守恒校验。

> 项目仅使用模拟数据，不处理真实资金、客户信息或交易指令。

## 业务背景

行业标准《证券公司与资产管理产品管理人及服务机构间对账数据接口》明确，对账发生在证券公司日终完成清算后，数据涉及资金资产、证券资产、资金明细及待交收证券资金等多类接口，并同时存在实时 JSON/HTTP 和非实时 xlsx 文件两种方式。现实系统还需要面对交易、资金、持仓、费用批次到达顺序不一致，以及小范围更正触发全量重跑的问题。

## v2 聚焦的一个优化点

**上游小范围更正时，避免全量重算机构对账单。**

- 为每个机构账户的交易、资金、持仓、费用输入生成稳定 SHA-256 指纹。
- 输入未变化时直接复用上一版本；费用或其他批次更正时，仅生成受影响账户的新版本。
- 出单前执行数据完整性、资金守恒和持仓守恒三类闸门；失败时阻断出单并给出可复核原因。
- 保存上游批次号、指纹、版本、差异维度和生成时间，支持审计追溯。

## 基础对账能力

- 两阶段匹配：优先使用成交编号精确匹配；编号缺失时使用账户、证券、方向和数量组成的业务键。
- 防误配：候选不唯一时不猜测，标记 `NEEDS_REVIEW`。
- 六类结果：匹配成功、金额差异、日期差异、待复核、内部缺失、清算缺失。
- 一一消费：同一成交或清算记录只能被匹配一次。
- 批次幂等与报告持久化：重复批次返回第一次生成的结果，便于日终任务安全重试。
- FastAPI、Pydantic、SQLite、Docker、pytest、ruff 与 GitHub Actions。

## 可复现实验

```bash
python -m app.benchmark --accounts 10000 --correction-ratio 0.01
```

实验先生成 10,000 个模拟机构账户，再更正其中 1% 的费用批次。对照组执行全量重算，增量引擎对全部账户计算指纹，但只重新生成发生变化的账户版本。运行结果保存在 `benchmark_result.json`，简历只引用真实运行结果。

本机实测结果：全量方案重算 10,000 个账户；增量方案重算 100 个、复用 9,900 个，重算范围减少 99%。墙钟时间受机器和 SQLite 配置影响，因此简历不使用耗时数字。

## 对账流程

```text
内部成交 + 清算记录
        ↓
成交编号精确匹配
        ↓ 未匹配
唯一业务键候选匹配
        ↓
金额/日期核验 → 自动匹配或异常分流 → 批次汇总与审计报告
```

## 本地运行

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e '.[dev]'
uvicorn app.main:app --reload
```

提交示例批次：

```bash
curl -X POST http://127.0.0.1:8000/v1/reconciliations \
  -H 'Content-Type: application/json' \
  --data @examples/sample_batch.json
```
